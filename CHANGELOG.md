# Changelog

## Unreleased

Kiro CLI 3.1 is supported. It runs each hook under `node` and `bun` below the outer `kiro-cli`, and there is no `kiro-cli-chat`.

On a host without `/proc` start times, such as macOS, the hook cannot tell the outer `kiro-cli` start time to better than one second. It used to record that process as the pane's owner anyway, and after that a Stop never ended the turn, so the plugin's pane state stayed busy. The hook now records no owner in that case, and Stop ends the turn. A pane file saved by 0.1.0 can still hold such an owner. The next hook in that pane drops it, so a `kiro-cli` that kept running across the upgrade does not need a restart.

This restores the plugin's own pane state and its Herdr TUI reports. It does not change what the Herdr App shows on macOS: there the App status comes from herdr-core and Kiro, not from this plugin.

The hook no longer runs `herdr report-agent` or `herdr release-agent` from an App terminal. Those are for a Herdr TUI pane only.

If `kiro-cli` is killed in the middle of a turn on such a host, that session stays busy in the plugin's pane state. A later session in the same pane ends its own turns but does not clear the killed one. Deleting that pane's file under `$XDG_STATE_HOME/herdr-kiro` (by default `~/.local/state/herdr-kiro`) clears it.

`PreCompact` and `PostCompact` are not registered. Kiro sends no Stop after `/compact` (seen live on Kiro 3.2.0), so a busy mark set there would never clear. If those events arrive anyway, the hook returns without reading or writing anything.

Uninstall puts a file of yours back with the mode it had before install. It used to come back as 0600.

## 0.1.0

herdr-kiro reports a Kiro CLI session to the Herdr App with OSC 7501 on the pane tty, and still reports the Herdr TUI with `herdr pane report-agent`. Kiro CLI 3.0 is the supported CLI. Interactive `kiro-cli chat` starts on V3. A saved `chat.agentEngine` of `v2` still selects V2. The hook writes `app=kiro-cli`. A status whose app is `kiro` is still this program.

A running turn is `state=working`. A chooser or the workspace-trust dialog is `state=blocked` with `kind=permission`. A question panel is `state=blocked` with `kind=question`. A finished turn is `state=done` on the App and `idle` on the Herdr TUI. That OSC word stays `done` after the pane is seen. `herdr-app ls` shows the unseen turn as done and idle once `herdr.seen` is the turn. The painted Agents section keeps a focused row under Done until that row is left. The TUI report is not followed by `release-agent` while `kiro-cli` is running. A live pid with an empty token, `sec:` plus a whole-second start, or a bare whole-second start is not an exit and is not painted. A proven owner ends `state=done` on that pane.

A failed App screen read is none. It is not an empty screen, a prompt, a banner, a start, or aggregate_zero, and it is not refresh. It is not explained, it is not painted from that missing screen, and a held working banner does not count. It does not end the turn. An empty App read is not the Kiro CLI 3.0 chevron, so it does not report idle or paint `state=done`. A TUI pane that inherited `HC_TERMINAL_ID` reads that pane and does not write OSC. A failed read of that pane does not end the turn. `hc` is herdr-core and has no status-set command. The pane device is that owner's stdout tty. A missing fd lookup, an ambiguous result, or an unproven owner writes nothing. The write does not fall back to the controlling terminal or `/dev/tty`. A proven outer exit writes `state=done` on the held tty only when that fd's pid is the owner. A mismatched or unconfirmed held pid writes nothing for every stored phase, including proven, idle_clear, weak, and exited. That includes touch_aggregate, record_aggregate, refresh, touch_partial, blocked, and a working paint, and does not open the live stdout. There is no pane file, aggregate, busy, grace_until, generation, seq, seq floor, log, watcher, watcher_at, watcher_started, or watcher pid file. The owner row stays. A screen read does not delete a pid file. reap is the runtime deletion, and only commit_pane applies it, only for a confirmed dead pid or a confirmed token mismatch. A live pid whose token matches is not reaped when only the comm name differs. A none result, including fault and refuse_watch, returns before any I/O and unlinks nothing. The watch result runs the watcher and is not none. Watcher exit unlinks a pid file only through that reap. Uninstall removes a pid file when the process is absent from the snapshot, and removes one after a signal only when the uid, a fractional `fine_start` token, and the comm basename match. A live `sec:` token, a bare whole-second start, a token or comm mismatch, a snapshot error, or a different uid is left in place. The `pids` directory is left in place. A none result from `pane_transition` does not drop that row, and it does not assign phase, busy, or a tty. A proven owner already at aggregate zero refreshes only the busy timestamp, with no seq change and no watcher pid, and that Stop does not also paint done. A weak or unproven owner at that zero changes nothing. Blocked is painted only when the table returns paint_blocked for a proven owner, and only commit_pane emits that OSC. A watcher exit with no proven owner, including an agent that is gone and an empty owner table, does not write OSC and does not call `release-agent`.

doctor accepts a default 3.0 install, where `chat.agentEngine` is unset. The headless workflow suite passes `--trust-all-tools` because a headless run that omits it stays on V2. The approval check does not pass that flag.
